# Design Decisions (ADRs)

This folder is the permanent home for the architectural decision records (ADRs) that define PandaTrack's design system. Each ADR captures one decision: its context, the decision itself, the alternatives considered, and the consequences. They remain in force unless a later ADR supersedes them.

These decisions originated in the redesign subproject (historical context) and were graduated here as their permanent home. The content is preserved as written; only the home changed.

## How to use this folder

- Before changing a reusable interface pattern, check whether an ADR already governs it.
- When a change introduces a lasting design or architecture decision (a new cross-feature pattern, a tradeoff, a policy), add a new numbered ADR here in the same change. See `.agents/rules/adr-decision-records.mdc` for when an ADR is required.
- ADRs are append-only history: do not rewrite a decision after the fact. To change a decision, add a new ADR that supersedes it and note the supersession in both.

## Status legend

- **accepted** — in force; build to it.

- **superseded** — replaced by a later ADR (named in the record).
